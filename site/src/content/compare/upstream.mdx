{site.name} is an Apache-2.0 derivative of an open-source agent workspace. Most of the code is inherited; required attribution is in <a href={site.links.notice} rel="noopener">NOTICE</a>, and <a href="/lineage/">the lineage page</a> lists what we carry on top. **The original project has a more mature legacy adapter.**

The upstream project is further along than the version we forked. Since its 0.6 release it docks several agents besides its original agent CLI, and it ships installers and a container image. We forked at 0.5.0, before all of that.

## What we add

- **A registry of eleven runtimes with the legacy adapter optional and last.** Five of our ten other runtimes are ones the upstream project does not dock: Cursor, Kimi, DeepSeek Harness, Grok and Droid. Both of us dock OpenCode. <a href="/registry/">The registry</a> says what is verified on each, which today is little.
- **A harness router for subagents.** Chat runs the one harness you choose; the router can send a spawned subagent to another installed harness and never forwards provider traffic. It is registered and unit-tested, not verified on a live run; whether upstream has an equivalent is not checked yet.
- **No first-launch account with us.** You still need your agent vendor's own login.
- **Endpoint removal.** Upstream's update feed, app catalog and telemetry are off by default; the one address left is the embedding download in the table.
- **Proof pages.** A check on this site links to a dated row on <a href="/verified/">the verification log</a>.

## What we lack

- **Installers, a wheel and a container image.** The intended install is from a reviewed source checkout; public source is available on GitHub.
- **The agent's own tools on other harnesses.** Upstream passes its tools to every backend except Pi. In Warding, availability depends on harness integration, permission mode and session identity; these workflows remain unverified.
- **KAS**, which upstream docks and we do not yet.
- **Maturity.** Upstream is at a later version, with more people on it.

## Fork strategy

We track upstream and rebase the carry-set onto it; the carry-set is listed on <a href="/lineage/">the lineage page</a>. Upstream facts on this page come from its own documentation and changelog, read on 2026-09-25; the original attribution is retained in NOTICE.
